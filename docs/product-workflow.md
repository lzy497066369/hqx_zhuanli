# 产品简介驱动的创作流程

## 当前默认链路

发明专利（产品型）和实用新型共用新的产品工作区。外观设计和软件著作权保留原有模板流程。

1. 默认输入产品基础名称，选择系统提出的一个技术问题，自动确定初步名称；已有描述和企业名称可选。已有特征拟名方式保留为可选入口，历史项目继续沿用原编辑方式。
2. 保存名称后，独立调用文本模型检查**所有已选特征、资料与初步名称**的逻辑关系。检查名称/客体、连接、运动、空间、材料/环境、功能条件、安全/制造边界七个维度。
3. 有实质矛盾时返回明确原因及可选的删除、替换、同步改名方案。用户逐项取舍后重新检查；不静默删特征，不直接放行互斥选择。合理缺省和需要工程核实的参数列为推定，不强制用户手工补结构或坐标。
4. 检查通过后自动生成统一结构方案及保护层次，再按稳定编号和原名称复核、修正并冻结技术依据。从冻结方案派生既有产品简介；结构中间结果与复核记录分开保存，复核失败可从检查点续跑。详见[文本流程](product-text-workflow.md)。
5. 先将完整简介注入主体图模板，通过 `images/generations` 生成主体图（轴测），确定部件形状、数量、位置、配色和装配状态；再将同一主体图作为实际图片上传到 `images/edits`，依次生成前视图、俯视图、右视图，仅改变观察方向。图片请求在服务进程内全局限制为一次一个，避免多个项目同时生成时争抢上游生图资源。简介中的剖视、分解、局部移除和状态对照安排不用于彩色预览。服务商与图片模型须支持 multipart 参考图编辑接口；不支持或调用失败时明确报错并保留主体图，不降级为独立文字生图。预览图不要求也不允许出现数字或标注（生图模型画的数字不可靠，已撤回）。每个视角只提交一次；某个视角失败时其余视角保留，重试只补缺失视图。预览只用于确认外形，精度要求不高。
6. 用户可确认或重画。重画弹窗包含输入框、方向选项、必要时的澄清问题；上下文保留前轮答案，信息足够便停止询问。没有问答轮数或重画次数上限。结构变更会再次进行逻辑检查并生成新的完整简介和四张新预览。
7. 明确确认**当前版本**的四张预览后，进入 CAD 阶段：
   - 浏览器把四张预览压缩到 1024 像素以内，与简介一起交给视觉模型；视觉模型输出一个 FreeCAD Python 脚本（只允许 `FreeCAD`、`Part`、`math`，必须定义 `build_model()`）。
   - 服务端对脚本做静态白名单校验（禁止文件、网络、GUI、反射、双下划线、顶层调用），不通过时让每个模型针对校验问题最多修正两次；仍不通过就放弃，不执行任何代码。
   - 在隔离的临时目录里用 `freecadcmd` 执行受限脚本（受限 builtins + 只放行白名单 import + 超时强杀），得到统一三维模型的三角网格。
   - 正式附图按技术需要安排1至8张整机、局部、剖视或状态图。实体编号从可见几何确定，孔槽等局部编号绑定所属实体的表面锚点；完整标号、真实剖切、图文核对、检查点与资源限制见[专利附图流程](patent-drawing-workflow.md)。
   - 再从冻结技术字段生成权利要求、说明书与摘要，保存草稿后复核文字并应用修正；附图说明与附图编号仍由服务端按真实清单固定生成，不由文案模型编造。
8. 在生成完成页或项目材料预览中下载 `.docx` 或 `.pdf`，包含摘要、权利要求书、说明书和按实际清单排列的黑白附图。两种格式共用已校验的正文、附图顺序、版本与图片摘要检查。产品简介、提示词、复核日志、工程验证任务和建模记录保存在项目中，不附入正式正文；复制/TXT 同样只取正文及既有附图说明。

PDF 在浏览器本地生成，采用 A4 分页与逐图独立页面，嵌入本地 Noto Serif SC 字体的已用字形，支持中文复制、搜索。首次导出按需加载生成器及字体，不请求模型或外部字体服务。最终文件从页面内容重新打包，清空文档信息字典、自定义属性、XMP、编辑记录及文档标识，不保留标题、作者、创建程序或创建/修改时间，也不在文件中遗留被移除的元数据对象；不修改历史下载文件。

**参考图路径：** CAD失败后保留已确认预览和成功检查点，可生成AI黑白参考图，但参考图不能替代通过完整标号及结构核对的附图。正式成品须重试完成CAD附图核对。

## 代码入口

Word 元数据只写入实际文档标题和本次导出时的创建、修改时间，不再写入固定品牌作者或生成过程描述。未采集的作者、最后修改人、修订次数、累计编辑时长不填，也不采用 Word 库的 `Un-named` 和默认修订号。再次用 Word 编辑保存后，属性由 Word 按实际操作更新；此调整不修改已有文件。

- `src/features/product/ProductWorkflowWorkspace.tsx`：页面、去矛盾、重画澄清、四图预览确认、CAD/兜底成品、分阶段恢复。
- `src/features/product/productWorkflow.ts`：类型、数据校验、版本门禁、原始选择快照、持久化校验（`previews`、`cad` 与旧版 `preview` 兼容）。
- `src/features/product/productPrompts.ts`：四个彩色视角模板、黑白模板、附图登记表（`FIGURE_CATALOG`）与 CAD 视角定义。
- `src/features/product/productWordExport.ts`：SVG 附图栅格化与纯黑白化、预览压缩、Word 打包。
- `server/productWorkflowAi.ts`：逻辑检查、重画澄清、主体图参考预览、CAD 路由及四阶段文本服务入口。
- `server/productTextAi.ts`、`server/productTextPrompts.ts`、`src/features/product/productText.ts`：结构与文字四阶段、统一提示词、技术资料、部件身份、原子补丁、字段白名单和版本绑定。
- `server/productCad.ts`：视觉提示词、脚本静态校验、FreeCAD 探测与隔离执行、附图投影、签名。
- `server/meshFigure.ts`：三角网格正交投影 + 深度缓冲隐藏线消除 → SVG，无外部依赖，可离线测试。
- `server/productImages.ts`：独立图片服务凭据、单次生图调用、图片下载及安全限制。
- `server/productProof.ts`：服务端 HMAC 结果签名与版本校验。
- `server/drawingAi.ts`：本机 API 中间件和配置读取。

原来的结构模型编译、几何绘图与 V2 文案工具仍保留，用于旧数据与相关代码的兼容；它们不再是新产品流程的前置门禁。旧版单张三视图预览（`preview` 字段）打开后仍保留显示，但不能用于确认，需要重新生成四张预览。

## 服务端配置

仅使用 `.env.local`，不要使用 `VITE_` 前缀。现有文本模型配置保持不变：

```dotenv
AI_IMAGE_BASE_URL=https://api.psydo.top/v1
AI_IMAGE_MODEL=gpt-image-2.5
AI_IMAGE_API_KEY=填写具有生图权限的服务端密钥
AI_IMAGE_SIZE=
AI_WORKFLOW_SIGNING_KEY=

# 视觉模型：不填则复用 AI_MODEL（必须支持 image_url 输入）
AI_VISION_MODEL=
AI_VISION_BASE_URL=
AI_VISION_API_KEY=
# FreeCAD 命令行程序；不填则自动探测 PATH、%LOCALAPPDATA%\Programs、Program Files 等常见位置
FREECAD_CMD=
FREECAD_TIMEOUT_MS=300000
```

FreeCAD 安装：Windows 执行 `winget install FreeCAD.FreeCAD`（本机已安装 1.1.4，路径 `%LOCALAPPDATA%\Programs\FreeCAD 1.1\bin\freecadcmd.exe`）；Linux 可用发行版包或 AppImage；macOS 为 `FreeCAD.app/Contents/Resources/bin/FreeCADCmd`。更改环境配置后重启开发/生产服务。

## API 契约

全部为本机同源 `POST` JSON；支持 `Accept: application/x-ndjson` 进度流。

| 接口 | 输入 | 前置条件/结果 |
| --- | --- | --- |
| `/api/product/review` | `{selection}` 或 `{review,resolutions}` | 签名的通过/矛盾报告；取舍只能来自当前签名报告 |
| `/api/product/brief` | `{review}` | 仅接受通过逻辑检查的签名报告；返回签名的完整简介 |
| `/api/product/preview` | `{brief}` | 先主体图、再参考图生成三视图；返回签名的预览集合 `{id, briefId, viewIds, digest, images[4]}` |
| `/api/product/revise` | `{brief,dialogue?,input}` | 必要时返回带选项的澄清问题；足够明确时返回修改后的完整选择 |
| `/api/product/confirm` | `{brief,preview,confirmed:true}` | `preview` 只传预览集合的签名引用；返回版本绑定的确认凭据 |
| `/api/product/cad` | `{brief,confirmation,images}` | 同版本确认 + 四张预览 data URL（每张 ≤8MB）；返回签名的 CAD 结果（脚本、网格摘要、实际附图清单及SVG） |
| `/api/product/structure` | `{review}` | 自动生成并签名结构检查点；brief 可接收 `{review,structure}` 继续复核 |
| `/api/product/draft` | `{brief,confirmation}` | 仅从冻结技术依据生成正文并签名草稿检查点 |
| `/api/product/materials` | `{brief,confirmation,figureIds?,draft?}` | 复核当前草稿；`figureIds` 只能取登记表中的 id（默认四个 CAD 视角）；返回签名文案及独立复核记录 |
| `/api/product/figure` | `{brief,confirmation,templateId}` | 兜底：只接受已启用模板与同版本确认；返回实际黑白结构图 |

简介、预览、确认、CAD、文案、附图都绑定简介版本。改动名称/选择后旧结果不能混用；服务端拒绝伪造的通过状态、被修改的简介、被改动的预览集合和跨版本确认。

## 重试、恢复与存储

- 每个预览视角只发一次上游生成请求；网络失败、超时或权限错误不会自动重复调用生图。主体图先生成，成功后其余三个视角依次上传同一主体图。图片请求在单个服务进程内全局串行，包括不同项目和附图任务；主体图失败不提交三视图；某个派生视角失败只重试该视角并复用主体图，派生图缓存绑定主体图摘要，避免混用不同主体图。等待轮到请求时可以取消；上游单次超时从实际获得请求名额后开始计算。
- CAD 阶段：初始脚本格式每个模型最多修正两次；确定性建模/附图核对失败最多修正六轮（含初次最多七次完整尝试），每轮仍执行完整核对；核对或投影自身失败的重跑不占修正轮数，另有三次上限；修正调用本身失败（超时、上游错误、连续返回无法应用的 JSON）在原地重试同一轮，最多三次，不结束整个阶段；两轮只改附图计划仍未通过时允许改为修改脚本。修正请求只以本轮问题为准，历史问题仅用于识别重复，独立复核只看上一轮发现；核对或投影自身失败（核对超时、空轮廓、渲染超时/退出）直接重跑同一步，不调用修正模型。同一组问题在网格和附图计划都没变时再次出现立即停止，不重复付费核对。成功脚本、附图和已成功建模的配置模型有持久检查点；后续附图核对优先使用该模型，重试时复用已有成果。有界修正仍失败则保留成果与原因（不再清空已生成的附图和正文），不能当作完成。
- 同一服务进程内对相同简介版本去重，拒绝同时重复生成，成功结果有有界缓存。重启后内存缓存失效。
- 结构方案、正文草稿、文案、CAD 结果和兜底黑白图分别落库。一项失败时保留其余，重试仅补齐缺失阶段；技术版本变化后拒绝复用旧草稿和旧文字复核结果。
- 产品结果、四张预览与 SVG 附图保存在 IndexedDB，不依赖可能过期的外部图片地址。
- 保存上一版完整成果供放弃修改时恢复，不保留无限图片历史。恢复不重新调用模型。
- 在应用内切换到项目管理、工作台或其他项目时，已打开的产品生成会话保持挂载，请求继续运行；每个项目按 ID 和名称资料版本隔离，返回同一项目不会重复提交请求。
- 进度事件与阶段结果写入项目的 `productWorkflow.generation`，项目管理及预览弹窗实时显示当前步骤、已完成的六个阶段、等待确认、失败原因和完成状态。四张彩色预览仍需用户明确确认才能生成成品。
- 返回修改名称、停止等待、删除项目或关闭/刷新浏览器页面时取消请求，并阻止迟到结果覆盖项目。FreeCAD 子进程随请求取消被终止。刷新后历史运行状态标为中断，保留已有成果，需显式继续；本实现不提供关闭浏览器后的服务端后台任务。
- 客户端等待：文本/生图阶段 660 秒，CAD 阶段 1860 秒；均长于服务端预算（文本 600 秒、CAD 阶段总预算 1560 秒、修正循环 1200 秒、FreeCAD 默认 300 秒）。最终图文核对失败时页面最多自动续跑一轮 CAD 修图，保留原确认、正文草稿和页面上的附图。

## 图片、脚本与文档安全边界

- 生图凭据独立于文本凭据，仅服务器向配置的 HTTPS 地址发送；忽略浏览器提交的 key、model、baseUrl 等额外字段。
- 视觉模型输出的脚本视为不可信代码：静态白名单（只允许 `FreeCAD`/`Part`/`math`，禁止 os/sys/subprocess/socket/open/exec/eval/getattr/FreeCADGui/文档操作/双下划线）+ 运行时受限 builtins 和受控 `__import__` + 独立临时目录（`FREECAD_USER_HOME` 也指向该目录）+ 超时后整棵进程树强杀 + 用后删除目录。
- 浏览器上传给视觉模型的只是压缩后的参考图；附图来自服务端执行脚本得到的网格，与简介版本签名绑定，前端导出前核对每张 SVG 的摘要。
- 不把原始上游错误正文返回前端；FreeCAD 失败只返回截断的异常类型与信息。
- Word 中的附图把 SVG 在浏览器栅格化后转为纯黑白 PNG，无远程引用。
- AI 逻辑检查不等于工程验证；自动建模的尺寸是推定值，附图可能与真实产品有差异，必须人工核对。所有文案都是待专业审核的初稿。

## 添加其余黑白模板

兜底黑白图仍从 `PATENT_FIGURE_TEMPLATES` 读取；收到新模板后添加独立 `id`、标题和模板正文，并同步加入 `FIGURE_CATALOG`。不要复用结构图提示词假装是另一种视图。

## 验证

```sh
npm run build
npm run test:product
```

专项回归使用明确标注的测试图片、测试网格和模拟模型返回，不消耗真实模型额度，覆盖选择传递、版本校验、预览顺序、取消恢复、部分失败补齐、并发去重、模型投影、动态图单及 Word 图号、黑白像素、移动端与无障碍等行为。`tests/product-workflow-cad.spec.ts` 和 `tests/product-drawing.test.mjs` 另有实际 FreeCAD 建模、状态、复合件剖切、表面文字、尺寸端点及超时测试。最终视觉验收使用系统真实生成的复杂夹具正文和 104,440 三角面的模型；证据与边界见 `artifacts/patent-drawing-2026-10-14/final-clamp/`。测试几何不替代复杂结构验收。

真实付费测试需手动设置 `RUN_PRODUCT_LIVE=1` 后运行 `npm run test:product:live`。它会保存四张预览、四张 SVG 附图和各阶段结果到 `artifacts/product-workflow-2026-10-09/`，重新运行只补齐缺失阶段。
