# 专利文本工作台

独立、无数据库、无 npm 依赖的本地应用。输入产品名称，选择待解决的问题后，自动生成并检查结构方案、权利要求、说明书及摘要。当前版本仅输出文本，不生成附图，也不执行专利检索或工程验证。

## 启动

需要 Node.js 22 或更高版本。双击 `start.cmd`，或在本目录执行：

```sh
node server.mjs
```

浏览器访问 http://127.0.0.1:3210 。服务仅监听本机。更换端口可设置 `PATENT_TEXT_PORT`。

## 接口配置

按顺序读取上级目录 `.env`、上级目录 `.env.local`、本目录 `.env`、本目录 `.env.local`，后者覆盖前者；系统环境变量优先。现有项目的文本密钥在上级 `.env.local`，可直接启动。也可将整个应用目录单独复制出去，并按照 `.env.example` 创建自己的 `.env.local`。

必填 `AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`。使用兼容 Chat Completions 的 HTTPS 接口，支持流式响应和两个备用模型。接口密钥仅在后端读取，不发送到浏览器、不写入结果文件。

## 工作流程

1. 生成候选技术问题，用户选择一项。
2. 确定唯一核心改进与方案边界，按实际需要生成部件及结构特征，不设零件目标数量。区分独立零件、组件、局部部位、孔槽、配合面及所属关系。
3. 同时建立核心动作的触发、初始状态、约束、顺序、终态和通路依据；梳理独立项必要特征、从属项限定和仅实施例细节，再进行原有结构审查和修正。
4. 根据确定的结构和保护方案生成权利要求、说明书、摘要。重点展开改进结构，常规配套简写；篇幅随复杂度调整。撰写与文字复核输入均排除设计假设和工程验证任务，正式文稿只保存规定的正文属性。
5. 文本审查并修正，检查术语、标号、引用和摘要长度。

结构和正文均有程序校验，格式或引用检查失败会自动修正一次。未解决的关键结构问题会停止后续写作。模型审查不等同于工程或专利性验证。

结构复核通过部件编号和原名称定位修改对象，由程序查找部件；禁止模型按数组行号修改或整体替换部件表。编号、名称不匹配时整轮修改不落地并走原有自动修正。新增、删除不会改变其他部件的编号，删除后允许编号空缺。其余字段和文本复核沿用原有补丁方式。

任务和中间结果自动保存于 `data/`（已忽略版本控制）。刷新页面可继续查看；取消、失败或服务重启后可以从已完成阶段继续。可复制正文、下载 UTF-8 TXT，或下载包含完整结构及审查记录的 JSON。

“部件与结构”展示所属关系和核心动作，“保护方案”展示特征取舍，“设计记录”保存方案边界、结构保留理由、设计选择和工程验证事项；复制及TXT下载仅包含正文。历史任务保留原始方案和结果，没有新字段时仍可正常查看，新规则用于后续生成。

此次调整沿用原有四个阶段及完成、失败、待复核状态的判定，没有新增质量评分、合格门槛或验证阶段。没有接入附图、检索或仿真。

## 测试

```sh
node --test test/*.test.mjs
```

测试使用本地模拟接口，不消耗模型额度。实际运行应用会调用已配置的模型。
