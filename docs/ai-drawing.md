# AI 专利内容绘图接入

验证日期：2026-09-22

## 当前工作方式

当前产品工作区采用单向名称驱动流程：用户确认第 1 步名称和产品资料后，系统自动执行 **结构草案 → 离线编译 `PatentStructureModel` → 附图与部件 → 申请材料**。第 2 步的模型输出必须包含完整部件、连接、几何和运动关系；无效结果由服务端自动重试一次。连续失败时只返回统一失败信息，不要求用户手动添加部件或打开高级编辑。

第 3 步和第 4 步都只读取已确定的 `PatentStructureModel`，分别自动生成三张附图及部件标号、申请材料初稿。用户可重新生成或导出，但不能在当前工作区手动编辑结构事实。任何失败都不会覆盖已有模型、附图或文案。

模型输出部件几何数据，不直接生成不受控的 SVG 或执行代码。图中仍为一条引线加一个纯数字。旧的 `drawing-plan` 概念接口及其手动字段仅为协议兼容和历史测试保留，不是当前 UI 入口。

信息不足时返回具体问题；遇到不支持的关键形状则明确提示，不用通用装配图兜底。自然语言含义和工程可行性仍需专业核对，格式校验不能代替技术审核。

## 服务配置与启动

当前使用 Psydo，调用顺序为 `claude-opus-5-5` → `claude-fable-5-1`。设计主模型由 `AI_MODEL` 指定，联网检索主模型由 `AI_RESEARCH_MODEL` 指定，备用模型由 `AI_FALLBACK_MODEL` 指定，沿用主服务地址与服务端密钥。普通生成使用 `POST /chat/completions`；联网检索使用 `POST /responses`，按相同顺序尝试。主模型成功、请求被取消或超时均不调用备用模型。检索必须有真实的 `web_search_call` 和可核对引用；模型可用或接口返回 200 不等于检索通过。两个模型均失败时明确失败，不跳过联网检索，也不用未经检索的内容生成方案。

2026-09-24 的旧 Claude 配置实测：两个模型普通生成均返回 200；主模型 Responses 检索返回 400；备用模型在正式的 1200 token 检索参数下返回 200，但状态为 `incomplete`，只包含普通文本，没有 `web_search_call` 或引用。正式 `researchPatents` 调用未通过 `RESEARCH_UNVERIFIED` 校验。当前切回该 Claude 配置后，普通生成和联网检索应以本次实际运行结果为准；不能把普通文本冒充已验证的检索结果。

服务商要求自建客户端请求显式携带 `User-Agent`；当前后端统一发送 `zhichuang-workshop/1.0`，用于避免被兼容代理误判为无来源请求。若服务商返回 `429 All available accounts are currently rate-limited` 或长时间无响应，这是上游账户池限流/不可用，不是本地检索逻辑可绕过的问题；系统仍会阻止方案生成，不会伪造或跳过检索。

在项目根目录的 `.env.local` 中配置（**不要使用 VITE_ 前缀**）：

```dotenv
AI_BASE_URL=https://api.psydo.top/v1
AI_MODEL=claude-opus-5-5
AI_RESEARCH_MODEL=claude-opus-5-5
AI_API_KEY=替换为Psydo服务端密钥
AI_FALLBACK_MODEL=claude-fable-5-1
```

`.env.example` 不含密钥；`.env.local` 已被 `.gitignore` 排除。本次本地配置文件权限为 0600。不要将配置文件、密钥或含密钥的调试截图上传到仓库或聊天。已在对话公开的密钥建议轮换，更新此文件后重启服务。

开发运行：

```sh
npm run dev -- --host 127.0.0.1
```

Vite 服务端中间件读取本地配置并转发模型请求，浏览器只访问本机同源接口。

构建后运行（本次测试 Node 22.23.0，使用 Node 原生 TypeScript stripping）：

```sh
npm run build
npm start
# 默认 http://127.0.0.1:4173，端口占用时：
PORT=4175 npm start
```

`npm start` 同时托管 `dist` 和 AI 后端，只有静态文件托管的部署无法调用 AI。Vite `npm run preview` 也带相同中间件，便于本机预览。

**部署边界：当前为本机单用户服务，不是可直接公开的多租户后端。** 服务监听 127.0.0.1，AI 接口同时检查来源地址、Host、Origin、Sec-Fetch-Site。禁止直接放宽为公网代理；正式部署前需增加用户鉴权、每用户额度、审计及持久限流。

## 数据与安全

- 本机接口：`POST /api/utility/drawing-plan`。
- 只接受 `mode: "concept"`、`title`、`technicalField`、`structure`、`workingPrinciple`。概念模式只要求名称，保留无mode的旧自然语言接口兼容性；不转发客户端的密钥、模型、URL、企业信息或其他项目字段。
- 密钥仅用于服务端 Authorization header；不写入浏览器存储、前端 bundle、业务导出或接口响应。
- 页面调用前明确提示第三方传输、保密技术授权及可能产生服务费用。
- 模型内容按不可信输入验证：JSON、状态、文字长度、1–30 个部件、形状、有限数值、尺寸、内外半径、位置及旋转约束。禁止执行模型代码或插入模型 HTML。
- 检索响应上限 512 KiB，设计响应上限 256 KiB，入站请求上限 64 KiB；每进程最多 2 个并发、每分钟最多 6 次生成。
- 两阶段共用 240 秒超时，页面 250 秒等待上限；联网检索使用独立兼容模型，旧兼容接口的设计输出限制为概念模式 4000 token、技术模式 6000 token，当前名称驱动结构请求限制为 4500 token；取消、离开页面或修改内容会中止/丢弃旧任务。中止不保证第三方免计费。
- 不跟随上游重定向，不向用户透传上游响应、异常堆栈或密钥；401/403、429、超时、网络、错误 JSON、截断、拒绝都有明确反馈。
- 不记录真实请求内容日志；接口响应 `Cache-Control: no-store`。
- 未接入云端项目存储。采用后的结构、原理、几何、检索来源及 AI 假设/拟议改动仍由用户手动保存到原有浏览器存储。

## 检索证据及设计边界

- 检索请求只传名称和技术领域；可选结构/原理不放入公开检索请求。用户输入的技术领域仍可能包含敏感信息，提交前须核对。模型工具的实际外发行为由服务商执行，不受本机直接控制。
- 要求真实完成的 `web_search_call`，从工具 sources/open_page 与 message URL 引用交叉取证；仅正文声称“查到了”不算检索成功。
- 仅允许 HTTPS Google Patents 专利页，限制公开号和语言路径、去掉跟踪参数，拒绝账户信息和不可信域名。本机不抓取模型指定的任意 URL，避免 SSRF。
- 每次最多保留5篇去重来源，区分 search_result 与 opened。有打开操作记录不表示全文/权利要求已经审查；归纳来自模型，需对照原文。
- AI根据检索归纳明确提出“设计设想”，不得将尺寸、改进、工程效果或新颖性当作事实。网页内容仅作不可信技术资料，不能覆盖系统规则。
- 检索失败、未完成、无交叉验证引用、格式/几何无效均明确失败。主模型失败时尝试配置的备用模型；两个模型均失败仍阻止方案生成，不降级为未经检索的方案。设计阶段也遵循相同的回退顺序。
- 来源和检索归纳随采用后的方案保存，可展开查阅并进入材料TXT；编辑结构后旧图及旧引用失效，避免把旧检索当新方案依据。

## 已知限制

图形内核按 `src/features/utility/geometrySpec.ts` 的统一参数化协议输出透明线框，当前包括长方体、圆柱体、圆管、外齿直齿轮、内齿圈、圆锥体、球体、椭球体、棱柱、环面、螺旋弹簧和螺纹圆柱。协议不支持任意自由曲面、叶片复杂曲面和遮挡消隐；遇到这类关键形状必须明确返回 unsupported，不能用基础几何伪装。模型可能推定示意尺寸、误解结构或返回无法采用的方案；假设必须显示并由用户核对。复杂产品仍应转专业 CAD 建模，不能将本功能输出视为已完成工程或专利审核。
