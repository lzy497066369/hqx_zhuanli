# 账号独立工作空间

一个账号可以拥有多个工作空间。空间只属于创建它的账号，没有共享、邀请或权限管理；所有注册用户的 `users.role` 仍然固定为 `user`。

注册时自动创建一个空白的“我的工作空间”。已有账号第一次进入空间列表时也会获得个人空间。左侧空间入口可切换空间、新建空间和管理空间；管理窗口支持改名、修改简介及删除。

## 数据结构

`workspaces` 新增以下三个字段：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `owner_user_id` | `CHAR(36)` | 所属账号，外键指向 `users.id`；新个人空间固定为当前登录账号 |
| `name` | `VARCHAR(80)` | 空间名称，1–80 个字符 |
| `description` | `VARCHAR(500)` | 空间简介，可为空 |

完整字段：`id`, `owner_user_id`, `name`, `description`, `projects_revision`, `materials_revision`, `projects_initialized`, `created_at`, `updated_at`。账号和空间是一对多关系；新增 `(owner_user_id, created_at)` 索引。

项目、命名草稿和资料库继续使用原有 `workspace_id` 外键，不需要复制这些表。不同空间可有相同项目 / 文件 ID，但彼此独立。删除空间会级联删除该空间的所有项目、草稿和资料；删除账号会级联删除其空间。删掉最后一个空间后，系统创建一个新的空白个人空间。

结构迁移位于 `server/mysql/workspaces.sql`，自动记入 `schema_migrations` 第 3 版。迁移检查已存在的列、索引和外键，支持中途失败后再次执行：

```sh
npm run db:migrate
```

## 服务端隔离

账号身份由会话 Cookie 获取，空间身份通过 `X-Workspace-Id` 指定。服务端每次业务访问都验证 `workspaces.owner_user_id` 是否匹配当前登录账号；客户端传入的用户 ID、角色、owner 或替换的空间 ID不能绕过校验。跨账号访问和不存在的空间统一返回 HTTP 404，未登录返回 HTTP 401，没有选空间返回 HTTP 400。

空间管理接口：`GET /api/workspaces`（只列出自己的空间）、`POST /api/workspaces`（创建）、`PATCH /api/workspaces/:id`（修改名称和简介）、`DELETE /api/workspaces/:id`（需提交 `confirmName` 完整名称）。创建时 owner 固定取当前会话，不接受客户端指定。单账号最多 100 个空间。

数据库存储事务在锁定空间后再次验证 owner，防止删除和读写竞争。生成队列令牌按账号及工作空间绑定；旧 V2 后台任务查询也校验相同归属，不能查询其他账号或其他空间的生成任务。

## 切换与旧数据

所选空间按账号保存在当前标签页的 sessionStorage，刷新后恢复，各标签页可独立选择空间。切换先刷新输入中的命名草稿并等待数据库写入；保存失败阻止切换并提示备份。随后关闭当前编辑和生成页面，整页重新载入新空间，避免旧页面结果或缓存串入新空间。

历史共享空间 `default` 和原来的其他未归属空间保留在数据库中，`owner_user_id` 为 NULL，普通账号列表与业务接口不能访问这些空间。**不自动把共享项目分配给第一个登录账号，也不复制给全部账号。** 如果需要迁入某个账号，先明确原数据归属再做专门的数据迁移。

个人空间为初始空白；不自动导入当前浏览器的旧 IndexedDB / localStorage 草稿或项目，以免共用电脑时将另一账号的旧数据带入。旧浏览器备份保留。历史存储回归测试仍可显式使用 `AUTH_REQUIRED=false` 的独立测试配置。

## 验证

`npm run test:auth` 包含实际 MySQL 多账号隔离测试和浏览器空间管理测试，覆盖创建者不能伪造 owner、跨账号读写及修改删除拒绝、同账号不同空间的项目 / 草稿 / 资料隔离、删除级联、最后一个空间删除、即时草稿保存后切换、旧浏览器数据不混入、重命名及手机布局。测试账号自动清理。
