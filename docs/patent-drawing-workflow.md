# 专利附图生成与核对

本流程读取已有的产品简介及冻结技术结构，不修改结构设计、正文生成和正文复核的提示词。彩色预览仍为主体图及三个视角。正式黑白附图按要说明的结构决定数量和视角。

参考图用于附图组织、细黑线、白底、纯数字和外围无箭头引出线的样式依据；不同产品仍以自身冻结结构为准。它们不是待提交的新专利附图，也不是授权保证。

## 数据与流程

1. 从 `technicalSource.plan.parts` 提取所有稳定编号，包括实体、孔槽、区域及配合面；历史简介则读取原 `design.components`。局部结构沿所属关系找到真正实体，不重新编号。
2. 视觉模型输出同一 FreeCAD 模型和 `drawingPlan`。计划含 1 至 8 张必要附图，按 `figure-1` 起连续编号；可选择整机、正投影、局部、剖视及状态。每张图说明用途和本图可见标号，全套必须覆盖所有技术编号。
3. 脚本返回原实体编号到形状的映射。同一编号下的重复件保留为 compound，不额外添加材料强行融合。运行时只开放建模 API，禁用文件、网络和 GUI。FreeCAD 1.1 的 compound 工厂通过可信包装调用，避免受限命名空间中的访问异常。
4. 部件形状须有效；部件间实际表面距离及每个重复实例的连接都必须成立。孔槽锚点必须在所属实体边界表面，实体内部点不能代替表面锚点。状态图（包括状态局部剖视）通过完整模型副本的位移和旋转实现，核对实体集合、体积和表面积；复合件按每个真实 solid 分别剖切后组合，避免整体布尔运算漏掉重叠或接触的组成实体。剖面按部件使用不同方向及间距的剖面线。
5. 局部与剖视图可指定 `focus`，在同一模型投影上放大关键节点。轮廓使用隐藏线消除，标号只落在所属实体的可见像素；剖视图数字放在外围，留出内部间隙。小圆弧不再因短边过滤而断裂；MeshPart 同时约束线性与角度偏差，不靠删除零件降低复杂度；网格超过投影预算时按超出比例同时放宽两种偏差（曲面网格的面数实际由角度偏差主导，只放宽线性偏差不会减少面数），逐步回到预算内，只有连粗糙容差都容不下的模型才明确失败。剖面填充使用与轮廓相同的 0.1 像素坐标精度，减少冗余 SVG 小数位。
6. 标号程序核对之后，独立视觉调用核对实际渲染图片与冻结结构的形状、数量、装配、可读性及图名。结构或标号不符时保留文字，最多作六轮有界修正（含初次最多七次完整尝试），每轮重新执行全部核对；核对或投影自身失败的重跑不占用修正轮数，另有三次独立上限；修正调用本身失败（超时、上游错误、连续返回无法应用的 JSON）在原地重试同一轮，最多三次，不会因此结束整个附图阶段；两轮只改附图计划仍未通过时允许改为修改脚本，因为核对要求的终点状态图或新几何可能根本不在脚本里。整段仍受阶段总时限约束。修正请求只以本轮问题为准：早期实现把累积的历史问题当成必须满足的指令回灌，而历史坐标对应的是已经替换掉的几何，模型因此在互相冲突的要求之间反复改动；现在历史问题只用于识别重复，独立复核也只接收上一轮的发现。若仅为锚点表面距离或可见性错误，修正模型只返回附图计划，系统保留已通过实体及接触检查的原脚本，再执行真实几何、投影与视觉核对。核对或投影自身失败（核对超时、空轮廓、渲染超时或渲染进程退出）不是模型的错误，直接重跑同一步而不调用修正模型。继续失败时保存问题供下一次明确重试，不能把失败图片作为完成成果。
7. 文案接口必须提交已签名 CAD 结果，或复用服务端已完成的同版本结果。附图说明从实际清单生成，标记表包含全部技术编号。最终材料还会逐张对照实际生成的权利要求及具体实施方式作图文核对，不仅比较简介。最终核对返回 `CAD_VISUAL_MISMATCH` 时，页面保留已生成的正文草稿和已经在页面上的附图，按检查点重跑 CAD 阶段修图，再复核实际正文，最多续跑一轮；保留原确认及正文草稿，停止操作立即中止续跑。网络错误等其他失败不触发这条修图路径。`drawingDigest` 将材料绑定到实际附图的顺序、标题和内容摘要。浏览器展示和 Word 按同一清单排序。
8. Word 将黑白图片放在“说明书附图”部分，每图独立一页、图号在下方；正文“附图说明”列同一图号和完整标记表。生成记录不进入正式正文。历史已完成文档保留读取能力；历史未完成 CAD 在继续生成时升级为新附图流程。

同一轮投影会检查整套附图，将各图发现的问题分别汇总后返回，不在第一张图失败时结束。检查点另存去重后的最近40项历史问题，用于判断修正是否还有进展，以及供下一次明确重试时理解问题类型；独立复核只接收上一轮的发现，不用已经失效的坐标反复报错。实体尚未生成时仍无法执行后续图面检查，不能据此承诺一次发现全部问题。返修若只改说明、未改变失败脚本或附图计划，立即以`CAD_REPAIR_STALLED`停止；同一组问题在网格摘要和附图计划都没有变化的情况下再次出现，同样立即停止，不重复执行或再次付费核对同一版本。

视觉返修接收与核对员相同的实际黑白附图及图号映射，完整反馈独立于对外错误提示保存，每项最多2000字，不受通用错误320字截断影响。核对员给出`repairScope`：仅调整视向、剖切、放大和标注用`drawingPlan`，系统锁定脚本；有具体几何错误证据才用`geometry`。几何修正只接收最多12项`scriptEdits`局部替换，每项原文必须唯一匹配，不能提交整篇重写；拼接后的脚本仍经静态安全、FreeCAD、投影及独立视觉检查。最终正文核对失败也保留原图作为后续返修依据。

正文明确要求的表面状态文字由 `surfaceTexts` 声明，使用字体绘制；投影字体限制在18至80像素，按最终字号校验整个文字区域所在的可见所属平面，不得越界、遮挡孔口或写在背面；不以零碎几何手画汉字。正文给定的小间隙可由 `dimensions` 声明两个实际表面点及测量轴，每图最多一项；尺寸值由坐标差计算，显示前检查端点可见及放大比例。两种标注都不能绕过最终图文核对。

同一编号下的不同实体分别网格化，保留接合线并用不同剖面线区分，例如相互抵接的两只锁紧螺母。局部图的实体标号还须靠近实际可见轮廓，并避开裁剪产生的人工边界，防止引线看似落在空白处。

实体接触检查按几何复杂度优先核对简单实体，用精确表面距离建立连通树；已经通过其他实体连接的实体对不再重复求距，仍检查全部重复实例是否连通。同一命名状态只构建并检查一次，每张图使用独立副本作剖切。2026-10-16 对渠道闸门脚本在实际 Docker FreeCAD 0.20.2 环境中复测，原实现首次接触检查约87秒、开启状态检查约156秒，三张开启状态图反复检查导致超过300秒；优化后完整模型及8张附图网格约18.5秒。Windows FreeCAD 1.1.4 下8张SVG与优化前逐字一致；完整记录见 `artifacts/cad-timeout-2026-10-16/verification.json`。

图片分析发生暂时性网络、上游故障或单次超时时，具有冻结技术结构的任务可有界地改用同一份文字结构建模，所有脚本、几何及视觉检查照常执行。最终正文核对失败时清除旧附图缓存、保存问题和已成功的正文；重试修图及服务重启后复用正文，不重新改写技术内容。模型对旋转槽与直线随动件关系的理解可能出现误判，应通过必要的状态对照图说明，不能按错误建议改坏原有运动关系。

`/api/product/figure` 仍可生成 AI 黑白参考图，但未经完整结构和标号核对的参考图不能作为新成品导出。

## 长任务与恢复

CPU 投影在可终止的 worker 中执行。FreeCAD 与投影共用两路资源槽，等待队列最多 64 项；视觉调用期间不占用这两个 CPU 槽。请求取消时取消等待、终止工作线程或 FreeCAD 进程树，清理临时文件，释放名额。投影最多 120 秒，FreeCAD 默认 300 秒；服务端整段 CAD 阶段总预算 26 分钟（`CAD_TOTAL_BUDGET_MS`），其中修正循环另有 20 分钟上限（`CAD_REPAIR_BUDGET_MS`），浏览器为整个 CAD 阶段保留 31 分钟等待预算。预算取这个量级是因为上游单次调用常需 110 至 270 秒，复杂产品的有界修正实际上由时间而不是轮数决定；顺利或不再有进展时循环会提前结束，不会白白占满预算。预算用尽时保留正文、预览和附图检查点并提示可继续生成，不再让页面长时间空等。

模型调用的单次时限同时约束获取响应头和读取响应体，最长270秒；SSE收到`[DONE]`后结束读取，不等待连接关闭，也不等待上游确认取消。附图建模、结构核对和整个阶段的截止时间分别返回对应错误，不混用“单次结构生成”的文案。

同一附图任务记录已成功编写脚本的配置模型，后续修正、附图核对及最终正文核对优先使用它，避免模型冷却到期后重新等待故障主模型。记录只允许选择当前服务配置中唯一匹配的模型，不能注入新地址、密钥或模型；严格测试策略仍固定配置主模型。正文生成与正文复核继续使用原来的配置和流程。

脚本计划、渲染结果、核对问题和最终 CAD 均保存签名检查点。服务重启后可跳过成功阶段；API key 或签名密钥变化、技术版本变化、损坏记录均不能复用。默认目录是服务账号主目录下 `.local/state/zhichuang-workshop/cad-checkpoints`，可用 `CAD_CHECKPOINT_DIR` 设置。目录不可放在公开静态目录。单条最多 16 MB，总量最多 256 MB、64 条、保留七天；过期临时文件会清理。Docker 使用独立 `cad_checkpoints` 卷。

这不是关闭浏览器后继续执行的后台作业；关闭页面会取消在途请求，下次明确继续时从检查点恢复。上游模型服务的速率和可用性仍影响耗时。

最终图文核对返回 `CAD_VISUAL_MISMATCH` 时，HTTP 步骤结束但整轮生成名额继续保留，前端使用同一名额按检查点续修 CAD，再核对正文。正常完成、停止、终止性失败或前端用尽续修次数后释放名额；关闭页面后的空闲名额仍按原有心跳规则回收。避免把“发现需要修图的问题”当成整轮结束，使后续 CAD 请求或心跳以 `GENERATION_EXPIRED` 遮盖实际核对意见。
