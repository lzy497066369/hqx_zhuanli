# 知创工坊

基于 React、TypeScript、Vite 的知识产权材料创作应用。发明与实用新型采用“特征选择 → 逻辑校验与去矛盾 → 详细产品简介 → 彩色三视图与不限次数重画 → 确认后生成文案、黑白附图与 Word”的本机服务端流程。

## 启动

```bash
npm install
npm run dev -- --host 127.0.0.1
```
Docker启动
前端 `zhichuang-frontend`（Nginx）和后端 `zhichuang-backend`（Node API / FreeCAD）使用独立镜像。配置好 .env.local（模型密钥）和 .env（网关账号、来源白名单、MySQL 密码）之后
docker compose up -d --build
局域网用户经网关 http://192.168.0.58/ 访问，需账号登录；旧版迁移添加 `--remove-orphans --wait`，保留原 MySQL 卷。分别构建、更新前后端的命令见 [Docker 部署方案](docs/deploy-docker.md)。

打开终端中显示的本地地址（默认端口 5173）。构建与本地生产预览：

```bash
npm run build
npm run preview
```

## 已实现

- 登录、注册、退出和会话恢复已接入 MySQL；新注册用户一律为普通用户。默认管理员 `admin` / `admin123` 可进入专属管理控制台，管理用户、查看所有用户项目及 AI 请求日志。字段、接口和验证见 [登录注册说明](docs/auth.md)。
- 账号独立工作空间：一个账号可创建多个空间，支持切换、改名、简介和删除；项目、命名草稿、资料库及生成任务按空间隔离，见 [工作空间说明](docs/workspaces.md)。

- 工作台：项目概览、桌面四列创作入口、原创 SVG 线稿、最近项目、操作指南。
- 发明专利、实用新型、外观设计专利、软件著作权四类材料整理模板。
- 项目管理：新增、编辑和删除企业，填写公司及主营产品；点击企业进入该公司的全部专利，支持新增、搜索、筛选、生成进度、预览与导出，以及三个申报状态切换。详见 [企业与专利管理](docs/project-management.md)。
- 项目、草稿、阶段结果、文案与实际生成图片通过 MySQL 持久化并按账号 / 空间隔离；旧共享数据库及浏览器备份保留；存储失败及多页面冲突明确提示。表和字段见 [MySQL 存储说明](docs/mysql-storage.md)。
- 发明与实用新型支持下载含实际黑白附图的 Word 或 PDF 初稿；正文只包含摘要、权利要求书、说明书与说明书附图，其他类别保留 TXT 模板。PDF 支持中文搜索、复制及 A4 自动分页，导出时清空全部文档元数据（包括标题、作者、时间、创建程序、XMP 和文档标识）。
- 资料库：文件名称、大小、类型和修改时间保存到 MySQL，刷新后恢复，可移除；不读取或上传文件内容。
- 响应式导航与布局：1024px 及以上创作入口同排；较小屏幕双列。
- 原生模态对话框、焦点管理、未保存确认、键盘操作、reduced-motion 支持。

## 实用新型：第一步取名字

从工作台“实用新型 → 开始创作”或模板中心进入。产品建议与名称候选由 AI 生成，经本地规则复核；不是企业工商查询或新颖性判断。

1. 填写企业和产品名称，选择具体的核心产品／保护客体、实际结构特征及改进类型：可观察外形／截面的形状改进，部件安排／连接的构造改进，或二者共同作用。AI 特征建议必须按实际产品核对；可补充需排除的品牌／人名／型号。
2. 按主营业务匹配常见硬件方向（含食品加工、纺织服装）；用户明确填写的产品和结构优先。“加工”不再直接匹配机床，泛机械仅在没有具体领域匹配时提供防护罩方向。未匹配业务时要求补充产品，不随机套用其他行业产品。
3. 点击生成后，按钮下方显示候选数量或具体失败原因；失败时提供定位到对应输入项的入口，结果区不再停留在初始空状态。查看候选、匹配依据和字数；推测的产品 / 结构标注为“技术待确认”。可编辑或复制名称。
4. 对宣传词、已知排除词、句号、笼统客体、方法 / 软件主题等进行基础检查。必须确认名称与实际技术一致，才能保存到项目管理。
5. 草稿自动保存到 MySQL；生成时会向配置的 AI 服务发送必要的企业与产品资料。已保存项目支持再次编辑、刷新和跨浏览器恢复。确认保存后自动进入独立逻辑校验与彩色预览流程，能力边界见下文。

### 规则边界

- 按本项目业务要求：建议 15–25 字，超过 40 字阻断；不足 15 字只提示，不为凑字数编造特征；字母、数字及标点计入长度。
- 页面区分业务限制与《专利审查指南》的通常 25 字、必要时不超过 60 字要求，并提供国家知识产权局官方文件入口。
- “一种”是模板偏好；“高效、节能、新型、低阻力”等按本项目的严格业务策略拦截。不能用词库检查替代完整法律判断。
- 名称主体必须是所填产品本身：产品是原材料（钢材）时细化为保留该材料的实体产品（H型钢梁），是具体产品时必须原样收尾。名称、结构首位主体与整体图主体都落在该产品上，不得改成它的配件或加工设备（连接组件、夹具、机床）；用户产品本身就是配件时以其收尾。用户选择的结构特征体现为该产品本体上的限定（一种带腹板两侧对称夹持板的H型钢梁）。
- 不能自动识别所有商标、人名或型号；未联网检索、未判断新颖性、技术真实性或可授权性。候选不等于真实技术方案。
- 命名步骤调用 AI 并使用本地规则筛选；新产品流程另做逻辑检查，不声称完成专利检索或专业审核，保留预览确认和人工核实关口。

实现位于 `src/features/utility/`；独立测试位于 `tests/utility-naming.spec.ts`，覆盖规则单元、集成、系统与验收场景。

## 产品简介驱动的预览与成品（当前默认）

适用于产品型发明和实用新型。所有已选特征、结构资料和初步名称一并交给文本模型进行独立逻辑审查。矛盾必须由用户明确取舍，检查通过后生成详细产品简介，并把同一简介用于彩色预览、修改迭代、CAD 建模、申请文案与附图。

- 彩色预览为并行生成的四张图：主体图、前视图、俯视图、右视图；用户可以确认或不限次数重画。预览只用于确认外形。
- 重画支持文字、选项和必要的澄清问题；信息足够时直接生成新的完整方案，不设固定问答轮数。
- 确认预览后，视觉模型参照四张预览与简介编写 FreeCAD 脚本；脚本经静态白名单校验后在本机 FreeCAD（freecadcmd）隔离执行，生成统一三维模型，再按实际技术需要生成1至8张整机、局部、剖视或状态黑白附图，检查全部标号及图文结构后，按实际清单生成附图说明。详见[附图流程](docs/patent-drawing-workflow.md)。
- FreeCAD 不可用或建模失败时明确报错并保留检查点；可生成黑白参考图，但未经完整标号与结构核对的参考图不能作为新成品导出。
- Word 按实际附图清单嵌入黑白图，每图独立一页，图号在图下；完整简介、脚本、建模推定与提示词保留在项目记录中。旧版参数化结构模型相关工具和旧数据仍保留兼容。

流程、配置、接口、版本门禁和测试见 [产品流程文档](docs/product-workflow.md)。需要安装 FreeCAD 1.0+（Windows：`winget install FreeCAD.FreeCAD`），并可通过 `AI_VISION_MODEL` 指定支持图片输入的视觉模型。

真实生图与复杂 CAD 验证记录见 `artifacts/patent-drawing-2026-10-14/`。早期服务分组未开启生图的 403 记录属于历史结果；当前已取得真实预览与附图。测试报告分别记录模拟回归、真实几何、视觉核对和压力测试，不能互相替代。

### AI 服务启动

使用 `.env.example` 的变量在 `.env.local` 中配置地址、模型及服务端密钥，禁止使用 `VITE_` 前缀。本地配置已排除版本控制，密钥不进入前端。

```sh
# 开发：前端与 AI 服务中间件同时运行
npm run dev -- --host 127.0.0.1
# 构建后运行：需要支持 TypeScript stripping 的 Node（已测试 22.23.0）
npm run build
npm start
# 端口冲突时可用 PORT=4175 npm start
```

服务仅允许本机同源访问，公开部署前需增加账户鉴权及每用户限额。仅上传 `dist` 到静态托管不能运行 AI 接口。密钥轮换后需重启服务。容器化部署（含无界面 FreeCAD）见 [Docker 部署方案](docs/deploy-docker.md)。

以下诊断仅适用于保留的旧版结构 API；新版产品流程直接显示阶段错误和重试入口。旧版 STEP 02 结构生成失败时，页面显示诊断编号。用 `rg '页面显示的 UUID' ~/.local/state/zhichuang-workshop/patent-structure.jsonl` 查阅同一请求的检索、草案、修复及最终结果；日志位于项目和 Vite 静态文件根目录之外，仅记录时间、模型名、HTTP 状态、耗时、结束原因，以及检索失败的固定分类 `failureKind`，不包含密钥、上游错误正文或产品资料。此分类是从上游错误中推断的排查线索，不是服务商能力认证。STEP 02 的检索预算最多 15 秒，草案主/备模型单次最多 85 秒，总预算仍为 240 秒；检索未成功时只可依据已确认资料继续，不得伪称已检索。`AI_MODEL_TIMEOUT` 表示草案模型的单次预算耗尽，`AI_TOTAL_TIMEOUT` 表示整个请求的总预算耗尽。日志仅对启用此版本后发出的请求有效。修改服务端调用或密钥后需重启开发服务。

配置、安全约束、调用链与真实验证见 `docs/ai-drawing.md`；几何格式见 `docs/utility-workspace.md`。

## 前端范围

**已接入本机文本与图片服务及 MySQL 项目存储；每个账号可拥有多个独立工作空间，尚未接入正式申报服务。新流程不声称做过专利检索或工程验证。**

首次打开显示四个明确标注的示例项目。已整理状态只是用户手动设置的材料状态，不表示申请、授权或审核通过。示例项目导出的是待填写模板；完成新流程后导出 AI 申请材料初稿。两者都不是已经专业审核的正式申请文件。

项目及命名草稿保存在 MySQL，资料库保存文件元信息。每个账号拥有独立的多个工作空间，数据库容器使用持久化卷；重要信息请主动导出并另行备份。旧共享数据仍保留在库中，需明确归属后另行迁移。

## 代码结构

- `src/App.tsx`：工作台与功能页面、前端交互。
- `src/data.ts`：四类模板配置、项目模型、存储解析和导出函数。
- `src/components/Modal.tsx`：焦点管理与可访问模态框。
- `src/components/Illustration.tsx`：四类原创 SVG 插图。
- `src/App.css`、`src/index.css`：响应式布局与主题。
- `design-system/MASTER.md`：设计约定与业务边界。
- `tests/workspace.spec.ts`：集成、系统和验收自动化测试。

后续可扩展角色权限管理和数据库备份策略。
